## Design thesis

Rivet Kart's architecture is sound (authoritative 60Hz actor sim, snapshot interpolation, Threlte scene), but the game currently fails at four levels simultaneously: (1) the player's hands are betrayed (stuck drift keys, 110-250ms steering latency, rocket start that stalls everyone who plays naturally), (2) headline content is unreachable (the only shipped track has ZERO item boxes and boost pads, so shells/bananas/star/lightning/pads have never executed in real play), (3) the session loop breaks after one race (rematch softlock, stuck spectators, rooms vanishing from the lobby, the winner never sees YOU WIN), and (4) the car doesn't read as a machine (flames at the nose, headlights at the tail, camber-leaning wheels, 2.5-unit hover, no shadows, invisible camera shake). The thesis: Wave 1 makes the existing game TRUE — input integrity, netcode (snapshot pacing fix MUST ship with the interpolation buffer + local prediction since the 62.5Hz accident currently masks 20Hz choppiness), fairness (progress metric, off-road penalty, rocket start), the full session lifecycle with reconnect grace, item-system activation bundled with the five latent item bugs, and the visual-credibility floor (rig fixes, grounding, shadows, bloom-instead-of-pointlights, drift pose/skids, visible shake, HUD truthfulness). Wave 2 makes it FULL: audio from zero, track #2 (the already-built neon circuit) + race settings, CPU bots, per-car stats, time trial with ghosts, race telemetry, gamepad. Wave 3 makes it RICH: track-generator pipeline for tracks 3-N, impact VFX, item defense depth, progression/leaderboards, particle perf, pause/settings/mobile. Ordering principle within Wave 1: server truth before client feel, feel before juice; packages sharing race-room.actor.ts (the 2,400-line monolith) are scoped to disjoint function regions so serialized execution composes cleanly.
